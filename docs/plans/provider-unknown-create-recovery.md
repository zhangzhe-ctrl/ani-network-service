## 1. 已修缺陷和历史记录的区别

正常退出时，对已经返回的确定执行结果使用独立、有界的完成 context，并继续校验原 lease、epoch、版本和观察 fence。该修正避免确定的发送前失败因父 context 取消而无法落库；不能恢复已经丢失的旧回执，也不能把真正未知的 POST 写成未发送。

历史 VLAN 的 pending 提交与取消日志相邻，符合该缺陷的表现。但日志没有完整请求关联，当前对象缺失及 API Server 请求计数只能提供旁证。不能以反复 GET、等待固定分钟数或新测试通过作为自动清除历史 pending 的依据。

## 2. 已接受的决策：仅本实验的一次管理员恢复例外

用户已明确授权本实验恢复并复测，接受继续原创建的管理员例外。它是管理员决定继续原创建，不是 Provider 返回了“未发送”证明。无需先维护共享 API Server、修改网卡或重建数据库。该建议之后已获得上述本实验恢复授权；不扩大为通用产品开关。

范围固定为 run `lb02-09141908-2b3122` 中 VLAN `vlan_de1416d0a8d2473ba6da717f6282c290`，operation `0295db34-1441-4ba4-bf87-1523168c3f6c`，binding `feef8adb-7766-4d2b-a280-89c221f63d5a`。原 untagged 规格、Provider 名称、设备和保留占用不变。此例外不得扩展为任意资源超时后自动重发，也不能记为自动恢复门禁通过。

## 3. 历史通用接口草案（未实施，不阻塞本次实验）

1. 沿用现有平台管理员身份边界，新增受保护的 review/apply 恢复用例；不从任意请求字段制造管理员身份。review 纯读并输出目标、版本、原 pending、设备占用、只读 Provider 检查和计划摘要。
2. 本 run 的写入进程停止，确认旧进程退出、旧 lease 无效，保存并核对 PG 备份。直接读取原 Provider 名称；若已存在，走既有归属/UID/规格检查及正常观察，不套用 absent 恢复。
3. apply 必须同时匹配本次授权的精确 run/resource/operation/binding、expected_version、计划摘要和幂等键。非管理员、计划过期、活动 lease、UID 已存在、规格改变、删除已受理或错误对象一律拒绝。
4. 在现有事务/锁顺序中保存独立且不可变的恢复审计：管理员、理由、证据哈希、原 pending 全值、原 operation、版本和一次性授权。记录明确表达“管理员授权重试，历史结果仍不可证明”；不伪造 Provider 回执或历史成功。
5. 恢复原 operation 的执行资格，保留原 binding、Provider 名称和所有占用，由现有 worker/实际 adapter 继续创建。两次提交同一恢复请求只得到同一审计收据；不能手写 SQL 清空状态或由 fixture 直接创建产品 CR。
6. 创建期间遇到同名对象仍核对原归属、规格和 UID。后续删除继续原有前提和迟到对象检查；任何同名异 UID/迟到重建都作为冲突保留，不能为完成清理强删或悄悄释放占用。

一次恢复受理不等于创建成功，更不等于 Public 网络可用。后续 U09、删除和占用释放各自验证，报告保留本次管理员例外及其剩余风险，不宣称它解决了任意未知写入的严格恰好一次问题。

## 4. 通用接口未来若实施时的验证范围

沿用 biz/data/service 和持久 worker，先限于精确授权的平台未知 create，不顺带放开任意租户资源、未知 update/delete 或 UID 替换。新增持久审计使用追加迁移，历史迁移保持。

至少验证：真实 PG 中过期计划/错误 binding/变更版本/有效 lease/非管理员拒绝；无授权不重发；同一恢复请求幂等；恢复与删除竞争；恢复后继续原 operation；原请求迟到与恢复请求并发时核验原名称及身份；恢复后的正常删除和迟到重建冲突；数据库和 Provider 占用不得因例外提前释放。受控案例与本实验实际结果分别留存。

## 5. 尚不成立的替代方案

只替换 API Server 进程不足以直接宣称所有旧存储写入已经结束。etcd 写事务经过 Raft 提交，客户端取消后的结果仍需另外证明；参见 [etcd 事务及 Raft 请求源码](https://github.com/etcd-io/etcd/blob/v3.6.4/server/etcdserver/v3_server.go)。该源码只是反例审查输入，不是本集群 etcd 版本/执行结果证明。三台 API Server 当前健康的只读结果也不构成历史执行回执。

因此本提案不申请或执行共享 API Server/etcd 重启，不把维护当成一个已证明安全的恢复捷径。本次授权、记录恢复和复测已完成，旧事件按用户要求归档；后续继续 U09，不再就该旧事件索取授权或无上限轮询 NotFound。
