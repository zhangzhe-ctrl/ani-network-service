# 正常虚拟机与 ens35 的二层接入对照

2026-09-15，用户提供 `ssh ubuntu@172.16.102.30` 作为正常对照，并要求评估管理员诊断接口。本次授权用于有限网络诊断与接口建议，未恢复原 U09 服务、数据库操作或业务资源创建，未变更网络配置。

后续用户已明确改为 untagged 并要求配置 ani-01 继续测试，结果见[临时 IP 配置与后续测试](untagged-followup.md)。下文保留最初只读配置、主动 ARP 对照的时点；最新结果不再受此前 tagged 102 输入约束。

## 直接观察

[正常虚拟机](working-vm.json)经本地密钥 SSH 连接成功。其 hostname 为 ubuntu，MAC 为 `00:0c:29:91:aa:5c`；`172.16.102.30/24` 直接配置在普通 `ens34`，Linux 仅有 lo 与 ens34，未见 VLAN 子接口。默认网关为 `172.16.102.1`。两次独立检查中，ping 网关均为 2/2；邻居 MAC 为 `00:1e:08:2f:bb:17`。

[三节点同源对照](three-node-comparison.json)固定 ens35、ARP 源字段 `172.16.102.200` 和目标地址，只改变是否携带 VLAN 102 标签；每格发送两次请求：

| 节点 | untagged → .1 | tagged 102 → .1 | untagged → .30 | tagged 102 → .30 |
|---|---|---|---|---|
| ani-01 | 收到 2 次回复 | 无回复 | 收到 2 次回复 | 无回复 |
| ani-02 | 收到 2 次回复 | 无回复 | 收到 2 次回复 | 无回复 |
| ani-03 | 收到 2 次回复 | 无回复 | 收到 2 次回复 | 无回复 |

所有有效回复的 sender MAC 分别匹配正常虚拟机记录中的网关和 ens34；收到的回复均没有 VLAN 标签。untagged 项 NIC 接收计数增加 2，tagged 项增加 0，收发错误和丢弃计数均未增加。ani-01 的完整差异实验与后续缩小后的同源对照重复得到一致结果。

实验仅构造原始 ARP 请求的 source protocol address，未向任何接口分配 172.16.102.200，也未宣称该地址已获得分配。这里的短期探测方法不应直接成为产品接口的任意地址生成行为，正式能力应要求适用的源地址或保留地址。

## 修正此前结论

现在有直接证据证明：网关和 VLAN 102 内的正常虚拟机可以从三个 ens35 经 **untagged** 路径收到请求并回应。此前“可能 VLAN 102 未贯通到上游”的说法必须收窄，不能解释为整个 VLAN 或网关不可用。

[ani-01 完整差异实验](node1-differential.json)还发现：源地址 `0.0.0.0` 的 untagged 请求没有得到网关回复，但正常虚拟机 .30 会回应；改为普通源地址后网关也回应。此前 untagged 对照只用零源地址，而普通源地址只测 tagged，缺少关键的同源对照。旧结果保留历史时点，不继续用于判定 untagged 路径不可用。

## 解释与尚未核实的部分

当前证据最支持“主机期望的 tagged 102 与实际可用的 untagged 接入方式不一致”。正常虚拟机的 IP 直接放在普通网卡上，正好使用当前可通的来宾侧方式。

VMware 有不同的标签处理模式：VST 由虚拟交换机处理 VLAN，VGT 由来宾发送标签；vDS 的 VLAN trunking 对应后者。见 [VST 官方说明](https://knowledge.broadcom.com/external/article?legacyId=1010778)和[VGT 官方说明](https://knowledge.broadcom.com/external/article?legacyId=1010733)。这是模式解释，不是已经读取本环境端口组的证明。

本次没有 vCenter 管理连接，无法区分具体是端口组处理 VLAN 102、上游 access/native 映射，还是其他等效配置。**不能直接断言当前端口组就是某个 VLAN 值，也不能根据报文对照自动修改它。** 原输入明确要求主机发送 VLAN 102 标签；若改为沿用当前 untagged 路径，需要明确调整这个输入。若保留 tagged 102 要求，则仍需核对对应 MAC、端口组和上联透传。

ARP 回复只证明本次二层交换，不替代 Public 出站源地址、三类 LB 入口、业务后端身份或 U09 验收。原 Goal 整体仍未完成。

## 复现与范围

- [完整差异脚本](arp-differential.py)：两个目标、两种源字段和两种标签方式，固定每项两包。
- [缩小后的同源脚本](arp-ordinary-comparison.py)：只使用同一普通源字段，逐节点比较两种标签方式。
- 每份 JSON 保留实际 SSH 命令、脚本哈希、退出码、时间及计数；只使用本地已有密钥，未读取或复制私钥。新虚拟机没有免密码 sudo，因此本次在该虚拟机只执行普通用户的网络读取与 ping。
- 没有安装程序、变更网卡地址/路由/OVS/防火墙、创建 VLAN 接口或操作共享控制器。原 U09 服务与 API 转发未重启，原现场保留。
